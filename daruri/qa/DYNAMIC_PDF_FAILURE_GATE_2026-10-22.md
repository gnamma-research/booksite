All cases used only synthetic Reading Desk data. Every tested failure path retained the original browser-local data and made no cross-origin or non-GET network requests. Checks of the generated output's `hidden` *attribute* passed; the separate browser-visible check exposed the CSS defect.

### Defect A — misleading download link

`daruri/dynamic-editions.html` declares `.gn-dyn-download{display:inline-block}`, overriding the `hidden` attribute set by `dynamic-pdf/client.js`. The link is visible with `href=null` before any generation. Exact remediation proposed to the owner: `.gn-dyn-download[hidden]{display:none!important}` plus a regression test that checks actual browser visibility before, during and after generation failures.

### Defect B — stale selected edition

A successful **bilingual Reading + glossary** private PDF becomes the selected `generated-<SHA>.pdf` inside the personal exporter. If the user subsequently chooses **English Reading + index/concordance** and its apparatus fetch fails, the dynamic chooser reports failure yet the personal exporter continues to select the *previous bilingual generated PDF*. Preserve a user-selected exact version by synchronizing `GnammaPersonalExportInline.choose('editions/'+selected.file)` to the new verified published fallback when the profile changes, or use a clearly distinct selection model. Only activate new generated bytes after verified completion.

### Defect C — missing abort and timeout

A held network request causes both `gn-dyn-make` and `gn-dyn-personal` buttons to remain disabled; there is no Cancel control, no AbortController and no deadline. A later HTTP 503 restores the buttons. Owner should add finite network timeout, cancel/retry, and correct cleanup. If heavy pdf-lib work on the main thread cannot be cancelled, a Web Worker is a possible architecture, to be validated separately.

## Important limitations

- **No real low-memory native phone test performed.** Simulated JS memory exhaustion and input-size guards passed, but these do not measure iPhone memory pressure or a 500-note successful export.
- The tested offline case is an **uncached dynamic asset** that fails safely and succeeds after reconnect; it does *not* prove that a standalone published PDF is pre-cached and usable offline.
- This does not replace native iPhone PDFKit, Android PDFium, PDF.js, Acrobat or original-source Arabic Unicode/search release gates. These are separate workstreams.
- The test candidate is immutable `2dfc1e7`; release claims must be rerun against the **actual final merged** engine/preview/selector SHA.
- No static PDF or site asset was removed or overwritten. Maintain approved 120 apparatus variants and the canonical/fixed A4 editions until deliberate migration and rollback criteria are met.
