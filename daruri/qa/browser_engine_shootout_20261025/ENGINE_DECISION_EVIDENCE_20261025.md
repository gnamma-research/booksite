## Breakthrough: solve Typst Arabic at its cause instead of hiding tashkīl
Tested stock Typst 0.15.1 WASM (not just old Typst 1.0 wrapper) with the **actual Noto Naskh Arabic** fonts: `الضَّرُورِيُّ فِي أُصُولِ الْفِقْهِ` has 18 base Arabic letters but stock PDF extraction produces **39**. Unvowelled Naskh produces **25** from 18; Noto Sans Arabic or DejaVu Sans in the *unvowelled* sample can pass 18/18 in MuPDF, **but the fully vowelled version still corrupts**. Switching Gnamma to Sans/unvowelled is thus not an acceptable universal cure. See [font matrix #40156835568](https://github.com/gnamma-research/booksite/actions/runs/40156835568) and [vowel contrast #40153845189](https://github.com/gnamma-research/booksite/actions/runs/40153845189).

The Apache-2.0 Typsastra **Enhanced Unicode Typst** patch separates original logical Arabic codepoints from shaped visual glyph order, and matches Gnamma Arabic across **six real native PDF microfixtures** in MuPDF and Poppler, with qpdf success: [#40157018598](https://github.com/gnamma-research/booksite/actions/runs/40157018598). It also fixes the complete 231-page Scholarly PDF's Arabic COVER title word-for-word, including harakat, while preserving all notes/dictionaries/navigation. Enhanced native full QA: **416/416** eligible EN segment probes, **594/594** eligible Latin note probes, **391/412** 24-letter Arabic segment first/last probes. **21 Arabic longer-probe misses are NOT established omissions**: 5-letter overlapping kgrams of those passages generally appear at 85–100%, and page 23 visually/extracted spans contain parts that interleave across right/left columns. Stronger geometry-aware Arabic paragraph collation is still needed. Do not overstate these as full exact Arabic proof.

Enhanced fork source patches: Typsastra enhanced Typst commit `e3a60d5aa897d718b465efc3de0031c7d74efb3b`, Krilla `bb0873416484587814b9ecb682e262056f8effe2`; release tag `enhanced-unicode-v0.4.1`; package SHA256 `3a6859ec1ab3af153b231fb5d99db66585eede76211b95d5bd4705ad2036f539`. The standalone native Linux binary is **not** the browser engine. Original `typst-wasm/typst-wasm` browser framework is MIT (pinned `cf498a731ebbb801ccdfbff1bcca7ef9a94f9d31`). Research workflow [enhanced WASM build](https://github.com/gnamma-research/booksite/actions/workflows/daruri-enhanced-krilla-wasm-fork-compile.yml) attempts Rust 1.92 `wasm32-wasip2` patch/build; must confirm actual compile and browser worker integration **before** claiming fix on mobile web.

## Current editorial shortfalls of Typst and practical fix scope

1. Two-column alphabetical dictionary directory and printed target folios: **implemented and proven** in new converter. Sample *ibāḥa*: directory points to actual p156 article start. Same book retains direct lexicon references; full dictionary is not lost.
2. Qurʾānic quotation presentation: Q1/Q2 note bodies and links present, but approved framed citation callouts flattened; add Typst bordered box/tint and named citation/grammatical note styles, with explicit policies for section-local Scholarly vs bottom-page Study notes.
3. Running page header and footer (Contents / Subject Index / Dictionary) missing: add clean Typst context-sensitive page-header/footer links, ensure no duplicate annotations or extra printed text. Real tested cross references remain intact.
4. Concordance R/BA table is unnecessarily long/single column. Render via compact multi-column style with linked targets, fix page spans; preserve source values.
5. PDF native `/Names` tree has 0 versus 2856 WeasyPrint; PDF GoTo link destinations 660 original internal families and all 258 section TOC targets currently work. Implement names tree only if use cases (external PDF `#nameddest` links, historical annotations) show actual need; do not label every absent named dictionary entry a lost link.
6. Need full source-to-PDF Unicode collation, note-by-note complete/ordering, independent PDFKit/Acrobat and real iOS/Android low-RAM/open/copy tests. No exact tashkīl-sensitive word search requirement.
7. PDF output native enhanced ~5.54 MB vs stock direct WASM ~12.3MB; consider whether PDF size difference is exporter compression vs output fidelity and repeat with patched WASM. Native enhanced is NOT currently a user's browser-generated PDF.

## Engineering investment forecast (person-work-days; estimates, not commitments)
A. **Enhanced Typst/Krilla → existing WIT WASI-P2 browser framework**: **5–15 focused engineering days** for version/revision reconciliation, Rust builds, WIT component transpilation, worker JS mounting, true Blob PDF. Upstream changes/build failures might double this. Pin source and license; don't replace production. Existing workflow needs successful WASM compile and functional browser export before confidence.
B. **Typst scholarly style polish** (Q boxes, running headers/footers, concordance, pages, compact directory, dictionary proof): **5–12 days** depending on full-page editorial iteration. Two-column directory portion already done.
C. **Arabic and note QA / real mobile**: **8–20 days** (multi-reader, 416 Arabic units, all 625 notes, iPhone/Android and memory). Actual hardware access may require external testers.
D. **Vivliostyle-PDF Unicode emitter repair/fork**: at least **20–60 days** for correct ToUnicode/CIDs, malformed object streams, segmentation/RTL, real full book memory/performance, browser QA; costly and higher risk than Typst enhanced fork. It uses LGPL-3.0-or-later emitter with AGPL-3.0 pagination components: legal/license review required before product decisions.
E. **Brand-new PDF emitter or WeasyPrint/Pango/HarfBuzz WASM port**: **2–6+ person-months**, uncertain architecture, higher maintenance and mobile risk. Not recommended while the enhanced Typst fork works on real scholarly source.

## Recommendation / stop-go
**Best investment: patched Typst/Krilla browser WASM + incremental converter improvements.** The native enhanced engine has already proved the hardest complex-script semantics bug tractable without retypesetting from scratch, and Typst gives real direct client Blob. Maintain Paged.js/WeasyPrint as visual/style baseline and print fallback, not as default direct-PDF generator. Set objective gates: qpdf clean, 258 links and 153 dossiers, 157 historic articles/625 notes, correct logical Arabic copy in ordinary PDF viewers, 3 device classes mobile, no trace of personal notes or source file uploads. Promote only if all pass. Continue to serve signed original WeasyPrint Reference until then. Research branches and draft PRs remain nonrelease.
