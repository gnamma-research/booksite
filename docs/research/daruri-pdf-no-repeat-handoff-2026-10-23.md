## 1. Three architectures that must NEVER be conflated

1. **HTML → server/CI typesetter (WeasyPrint/Pango, Chromium print/CLI) → pretypeset PDF.** This is not ordinary-browser HTML-to-PDF generation. Some approved source pages were made this way and remain the certified baseline.
2. **Browser-local worker composition** of 12 SHA-signed A4 source PDFs + 15 reusable apparatus packets + 120 exact signed link/profile maps. This is the **published Stage 1** user-facing apparatus pathway. Five canonical editions remain separately published. Exactly 120 old complete apparatus PDF binaries have been retired, **not 120 scholarly options**. Restore only from the explicit pre-retirement archive if a verified rollback is authorized. No server receives users' private Reading Desk notes.
3. **Ordinary browser HTML/DOM + Noto/HarfBuzz/fontkit → vector outline + semantic Unicode PDF Blob**, with no pre-existing page PDFs, CDP, remote PDF emitter or print dialog. This **Stage 2** has powerful nonrelease proofs but is **NOT** yet an Arabic+English scholarly PDF edition. A 190-page Arabic-only research document is NOT one of the 12 approved A4 sources or the 120 apparatus editions.
